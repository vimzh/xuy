# xuy product requirements

xuy is a minimal, monochrome personal notes app for macOS, built in Rust with Dioxus Desktop. It should make it easy to start writing, find a note by folder, and choose a writing font.

## First version

| Area | Requirement | Acceptance check |
| --- | --- | --- |
| Launch screen | Show the local time and date on one line in the top-left corner, with the time first and the AM/PM marker omitted. Fade a full-width, monochrome ASCII scene gradually until it disappears about 60% down the page. Show **new**, **open**, **notebooks**, **settings**, and **docs** in that order, one option per row, with **Recently Opened** below. Use monochrome controls and monospace text throughout. [Scenes by ascii.rest](https://ascii.rest/#scenes) | The clock shows the current hour and minute and updates at the next minute. The date changes at local midnight. Each launch picks from the current theme's three scenes unless a scene is pinned in Settings. Light and Dark keep separate choices. Five borderless rows appear in a narrow centered column, each with a Hugeicons outline icon, label, and working shortcut. Click **notebooks** or press `⌘P` to open saved notebooks. |
| Notebook | Open a local folder with `⌘O`. Use `⌘P` to open saved notebooks or add an existing folder in place. Use `⌥⌘N` to create or select a folder and save it as a notebook. | Add a folder to Notebooks, relaunch, and reopen it with `⌘P`. When switching with unsaved edits, check that **Keep editing** preserves the draft. |
| Terminal and external edits | Open a local shell in a bottom panel at the current notebook folder. Offer open, minimize, and close actions in `⌘K`. Refresh notes written by other processes and preserve unsaved drafts when the disk version differs. | Run a command in the terminal and check that a clean note refreshes in Edit and Preview. Minimize and restore a running shell, then close it. Edit the same note on disk and in xuy and save the local draft as a separate file. |
| Notes | Use `⌘N` to create a named Markdown file, using `.md` by default. When no notebook is open, ask for a folder first. Open notes in edit mode by default and offer a rendered Markdown preview. Save automatically after one second without edits and keep `⌘S` for an immediate save. | Open a note, type Markdown, pause for one second, and check the file on disk. Reopen the note and check that its source is focused and ready to edit. Choose Show Preview to see the rendered content. |
| Session | Reopen the last notebook, sidebar folder, and active page in edit mode after closing xuy. If the notebook or page is unavailable, show a message and reopen what is still accessible. Returning to Home clears the open session. | Open a page in a subfolder, quit, and reopen xuy. Check the sidebar folder, active page, and editor focus. Move the page while xuy is closed, then reopen and check the notebook stays accessible with an error message. |
| Command bar | Open a centered, searchable list of commands with `⌘K`. Use Hugeicons for project, navigation, page, and settings actions. Offer theme, writing width, and zoom directly. Show Save Page and page history commands when available. | Open the bar from Home and while editing. Use the arrow keys and Return to run a command, and Escape to return to writing. Search for a theme or writing width, apply it, and reopen the bar to check its selection mark. |
| Markdown preview | Render CommonMark formatting plus tables, strikethrough, task lists, footnotes, callouts, and bare web and email links. Support images, heading links, and relative Markdown links and wikilinks within the notebook. Display raw HTML as text. Offer a saved Edit in Preview toggle, off by default. When enabled, edits to formatted text in Preview save to the note's Markdown source. Use `⇧⌘P` to toggle source and preview. Offer Side by Side in the view menu, the macOS Notebook menu, and the command bar with source on the left and a live preview on the right. | Enable Edit in Preview, change a formatted word, and check that it stays formatted after autosave. Disable editing and check that Preview is read-only. Toggle with `⇧⌘P` in either view. In Side by Side, type in the source and check that the preview updates while the source stays editable. Preview a note with a local image and a footnote. Follow a heading link and a wikilink to another page. Check that code and HTML source remain readable as text, and that the original Markdown is preserved. |
| Writing | Center a left-aligned text column in the editor. Put the sidebar toggle, note history, current folder, centered filename, writing-width menu, and view-mode menu in the title bar. Keep Home, Toggle Sidebar (⌘B), Edit Source or Show Preview, and Save in the macOS Notebook menu. Use `⌘+` and `⌘−` to zoom the app, including while editing. | Open two notes and navigate between them. Change the writing width and switch between Edit and Preview from the toolbar menus. Type in a note to hide the title bar and filename while keeping the text in place. Zoom in and out with the editor focused and check that typing can continue. Press ⌘B to close and reopen the sidebar. Move the pointer to the top or press Escape to reveal the title bar. |
| Note tools | Put **Outline** and **Highlights** in a secondary sidebar to the right of the editor. Show the active note's headings and subheadings in the outline and its highlighted passages in note order. Give it a dedicated column with a divider aligned into the title bar and a button to show or hide it. Let users jump to headings or select a highlighted passage for revision. Offer color and clear actions under Highlight tools. Store highlights in the Markdown file. | Jump to a nested heading in Edit and Preview. Select a highlight from Preview and verify Edit opens with its text selected. Save and reopen a highlighted note. Check all five colors in Light and Dark, collapse and reopen the sidebar, and check that it stacks above the editor in a narrow window. |
| Folders | Browse existing subfolders and use `⇧⌘N` to create one inside the current folder. Right-click the sidebar to create a page or subfolder in the current folder. List folders first and notes second, sorted alphabetically by displayed name within each group. Each note uses one row with its icon and title on the left and its local modification time for today or date for earlier days on the right. Omit Markdown extensions from titles. Load the note text when it is opened. Resize the sidebar by dragging its divider or using the arrow keys when the divider is focused. | Open a folder with notes modified on different days and check alphabetical order. Check that each row has just the icon, title, and right-aligned time or date. Right-click the sidebar in an empty subfolder and create a page and a folder there. Open a note to see its full content. Resize the sidebar, then close and reopen it with ⌘B to check that the width is retained. Use the up arrow beside the folder name to return to its parent. |
| Fonts | Offer iA Writer Mono, iA Writer Duo, iA Writer Quattro, Helvetica Neue, and JetBrains Mono. [iA’s font downloads](https://ia.net/downloads/fonts) | Check that the picker lists all five families and applies each one in Edit and Preview. |
| Appearance | Offer System, Light, and Dark under the macOS app menu. Use neutral tones in both themes and keep the writing page subtly distinct from the window decoration. Remember the chosen appearance. | Switch appearances while editing or previewing a note. Relaunch to confirm the choice is retained, then choose System to follow macOS. |

## Working assumptions

- xuy starts as a single-user app. Notes and folders are stored locally and can be reopened after quitting and relaunching without an internet connection.

## Design decisions for later passes

- Decide the window layout, spacing, and visual style step by step in the running desktop app.
- Decide how moving notes should work, where the font picker lives, and whether the selected font applies across the app or per note.

## Development sequence

1. Run a minimal Dioxus desktop window on the Mac with `dx serve --desktop`.
2. Build the launch screen, then the sidebar and editor as the visual direction is established.
3. Implement notes, folders, local persistence, and the editor font picker. Verify the first-version checks on the Mac.
